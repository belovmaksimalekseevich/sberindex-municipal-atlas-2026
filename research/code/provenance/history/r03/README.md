# Типология муниципалитетов

Воспроизводимый комплект сохранённых результатов и исходного кода кластеризации муниципалитетов по потребительским расходам. Он включает **504 месячных разбиения за 2023–2024 годы** и **28 отдельных контекстных разбиений за 2024 год**.

Основной месячный вариант — **NCut, K=10**; **SSE, K=10** — сильный контроль на той же геометрии. Годовой вариант — **context6 / KMeans / K=6** для 1666 муниципалитетов в 69 регионах. K20 используется для исследования детализации. Полная месячная сетка: SSE/Ward/NCut × K=4/6/8/10/12/16/20 × 24 месяца.

## Быстрый просмотр

Для просмотра нужен Python 3.11 или новее. Дополнительные библиотеки не требуются. Команды выполняются из каталога проекта и работают в Windows и Linux:

```text
python -B typology.py verify
python -B typology.py show
python -B typology.py show --month 2023-01 --method SSE --K 10 --id 1
python -B typology.py show --scope context --variant context6 --method KMeans --K 6
python -B typology.py summary
python -B typology.py export --out ../metrics.csv
python -B typology.py labels --month 2024-12 --method NCut --K 10 --out ../labels.csv
```

`show` без параметров открывает NCut10 за декабрь 2024. `export` сохраняет 532 строки с метриками, статусами и причинами неопределённости. `labels` выгружает ID, группу и индивидуальный SW выбранного разбиения. Выходные файлы должны быть новыми. Можно запускать скрипт по абсолютному пути из другой папки: входы находятся относительно самого скрипта.

`verify` проверяет состав и SHA всех файлов, неизменность научного ядра, полноту сетки, соответствие меток размерам групп, наблюдаемые поддержки и арифметику SW. Эти команды читают готовые результаты и не обучают модели.

## Область применения результатов

Каталог месячных входов содержит 2190 ID; фактическая поддержка меняется по месяцам, всего 50521 ID-месяц. Номера групп локальны своему разбиению. K20 не образует иерархическое продолжение K10. Годовой контекст — отдельное пространство: его шесть групп не складываются с десятью месячными и не служат независимой внешней валидацией. Последний тест не подтвердил дополнительную прогнозную пользу групп.

Для всех 504 месячных разбиений доступны SW, CH, AVI, AVU и MQ. S_Dbw определён в 175 случаях; в остальных 329 сохранены `null`, исходный статус и причина. Исторический флаг `eligible_for_comparison` требовал шесть определённых метрик; он не определяет существование разбиения. Сводка показывает среднее по доступным значениям вместе с их числом. Неопределённость не заменяется нулём; автоматического рейтинга моделей нет. SW из разных геометрий нельзя использовать как единый рейтинг, а отрицательный SW не является вероятностью ошибки назначения.

Месячные `semantic_profiles` содержат проверенные исправленные подписи осей: Total, продовольствие, здоровье, общественное питание, транспорт, маркетплейсы. Контекст имеет собственную схему и порядок признаков. [Карта контекстных входов](CURRENT_CONTEXT.md) перечисляет доступные файлы и исторические доказательства, не включённые в сокращённую поставку.

## Полный контрольный расчёт

Управление процессами проверено на реальном Linux: 10 процессных сценариев и четыре независимых сценария, включая вложенные detached-потомки, лимиты RSS/времени, исключения и завершение родителя. Приёмка привязана к точным SHA `compute.py` и `owned_processes.py` в `config/release.json`.

**Полный научный расчёт этой итоговой версии пока не выполнен.** Прежний полный результат принят и сохранён, но новая конфигурация и комплект требуют отдельного контрольного прогона. Приёмка управления процессами не подтверждает новый полный научный запуск.

Для расчёта требуется Linux, Python 3.11, точные версии библиотек, выделенные CPU0 и CPU7 и свободное место. Окружение Python и все результаты размещаются вне каталога поставки: его состав проверяется строго, поэтому создавать внутри него `.venv` или выходные файлы нельзя. Команды из каталога проекта:

```text
python -m venv ../.venv-sberindex
../.venv-sberindex/bin/python -m pip install -r requirements-compute.txt
../.venv-sberindex/bin/python -B typology.py verify
../.venv-sberindex/bin/python -B typology.py plan --out ../replay-control
../.venv-sberindex/bin/python -B typology.py compute --out ../replay-control --allow-real-fitting --exclusive-cpus-confirmed
```

`plan` печатает 26 шагов без создания процессов: январский пилот K10/K20, оставшиеся январские K с проверенным кешем пилота, 23 полных месяца и контекстную серию из 28 разбиений. `compute` запускает очередь последовательно, проверяет версии, ресурсы и целостность, требует новую папку вне поставки и останавливается при превышении лимита или неполном выходе. Автоматических повторов и продолжения незавершённой папки нет. Явные флаги означают разрешение на обучение и подтверждение исключительного выделения CPU.

Параметры `config/compute.json` назначены по измерениям принятого исходного расчёта:

| Параметр | Значение |
|---|---:|
| Одновременно вычисляющих процессов / потоков библиотеки | 1 / 1 |
| CPU месячной / контекстной задачи | 0 / 7 |
| Предел одной месячной задачи | 1800 с |
| Предел всей контекстной серии | 600 с |
| Общий бюджет вычислительной очереди | 18000 с, 5 часов |
| Предел измеряемого RSS дерева worker | 4 GiB |
| Минимум свободного места перед каждой задачей | 12 GiB |
| Рекомендуемое свободное место после установки входов и окружения | 32 GiB |

Базовая сумма прежних времён задач составляет около **2 ч 54 мин**. Это оценка переноса на сопоставимый CPU, а не измерение новой итоговой версии. Общая внешняя длительность контрольного окна — до **6 часов**: 5 часов вычислений и 1 час на проверки, сравнение, упаковку, выгрузку и закрытие процессов. Последний час не исполняется автоматически `compute.py` и должен быть зарезервирован отдельно. Подробные измерения: `provenance/MEASURED_RUNTIME.json`; окончательная ресурсная политика: `provenance/FINAL_RUNTIME_BUDGET.json`, её пояснение — `provenance/RESOURCE_POLICY.json`. Порог 12 GiB совпадает с успешно применённым исходным policy. Прежний выход занимал около 12,77 GB, архив — 3,41 GB; вместе около 15,1 GiB. Стартовые 32 GiB оставляют около 16,9 GiB, выше защитного порога. Первоначальная рекомендация 64 GiB в историческом файле измерений заменена этой окончательной политикой.

CPU7 задан в замороженном контекстном плане и должен быть доступен вместе с CPU0. Изменение этой схемы требует отдельного проверенного операционного изменения. RSS опрашивается каждые 0,1 секунды; это измеряемый предел, не квота ядра ОС. Linux pidfd и subreaper обеспечивают учёт detached/осиротевших потомков и их завершение при обычной остановке. Аварийное завершение самого управляющего процесса требует внешнего контроля сессии.

Результаты и остановки фиксируются в `RECEIPT.json` выходной папки. После завершения необходимо отдельно проверить полноту 504+28, сравнить метки, численные результаты и статусы с принятой сохранённой версией, сформировать экспорт и убедиться в отсутствии связанных процессов. Эти проверки, а также отдельный численный аудит и исследования устойчивости, не подменяются статусом `completed_504_plus_28`.

## Структура и происхождение

- `typology.py` — проверка, просмотр, сводка и экспорт сохранённых результатов.
- `compute.py`, `owned_processes.py`, `config/` — принятый Linux-механизм запуска и конечный вычислительный бюджет.
- `saved/` — компактные проекции 504+28 принятых результатов: ID, метки, размеры, SW, метрики и профили.
- `science/national`, `science/context` — неизменённые научные модули, входы и планы.
- `tables/` — таблицы принятого чтения: полная сетка, доступность метрик, старты и сравнения методов при одинаковом K.
- `provenance/` — источники, SHA, приёмки, измерения, первоначальные манифесты и история подготовки.

33 научных файла, входа и плана сохранены байт в байт. Новые манифесты описывают сокращённый состав; первоначальные доступны в `provenance`. Исторические календарные сроки в неизменённых научных планах относятся к исходной кампании; текущий адаптер использует относительные лимиты из `config/compute.json`. Крупные матрицы и журналы оптимизации не дублируются; источник каждого сохранённого результата связан SHA в карте переноса файлов.

Исходные данные сохраняют свои условия использования; для них не объявляется новая лицензия. Происхождение научного кода сохранено в исходных привязках. NumPy, SciPy, scikit-learn, psutil, joblib и threadpoolctl сохраняют авторство и лицензии разработчиков. Правила сопровождения репозитория и авторства коммитов: [MAINTAINERS.md](MAINTAINERS.md).
