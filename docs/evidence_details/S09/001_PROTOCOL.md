# Ограниченная проверка разрешения K6/K8

**Цель:** проверить устойчивость двух заранее заданных более крупных разбиений и показать цену укрупнения исходного расходного профиля G7. Принятый NCut10 остаётся неизменным; SSE — обязательное сравнение. Новый эксперимент не выбирает победителя автоматически и не превращает K6/K10 в иерархию.

## Зафиксированный объём

- Июнь и декабрь 2024 года; K = 6 и 8; NCut и SSE; прежние восемь seed и исходный выбор представителя по собственной целевой функции.
- В каждом месяце/K: полный fit и ровно десять 80%-ных подвыборок с **теми же упорядоченными ID**, что в RC68. Получается 4 полных + 40 draw-заданий, по два метода: **44 задания / 88 разбиений**.
- Полные опоры: июнь 2084, декабрь 2103; draw-опоры: 1667 и 1682 соответственно. K10 не пересчитывается: используются 44 принятых полных/draw результата RC68.
- Первые два задания: `R202412-K08-full`, `R202412-K08-D01`. Они являются частью 44, а не дополнительным пилотом. Основная очередь допускается только после калибровки и проверенного полного совпадения K8 с сохранённым декабрьским результатом.
- Совпадение ID делает сравнение **парным**. Это не новый независимый набор наблюдений; июнь повторяет также подвыборки прежнего шестимесячного исследования.

## Что остаётся неизменным

Исходные данные и смысл Total, признаки и веса, union-kNN15, Gaussian-веса, общий оценочный граф, исходный learner нормировки, seed, правила выбора представителя, формулы ICVI и обработка неопределённых значений. Полная нормировка берётся из принятой полной модели; в каждом draw исходная нормировка заново оценивается на выбранных ID по всем 24 месяцам.

У четырёх полных задач сохранено техническое `phase=admin`, `variant=full`, `task_role=full_baseline_fixed_reference`, чтобы `worker.py` оставался побайтно прежним. Это только ветка неизменной полной нормировки: **административных исключений и новых admin-fits нет**. Остальные 40 задач имеют `phase=stability`, `task_role=stability_draw`.

## Источники и условие численного переноса

`BASELINES.json` содержит восемь исходных полных разбиений K6/K8 обоих методов из принятого полного архива `final_control_run_r00.zip`: июнь `DT24-M0018`, декабрь `DT24-M0024`. Каждый исходный native result предварительно сопоставлен с соответствующим saved gzip принятой поставки r03. `SOURCE_BINDING.json` закрепляет SHA архива, точных native members, compact saved файлов, RC68 и контекстных входов.

При новом полном fit должны точно совпасть упорядоченные ID, метки, размеры, reference и geometry/graph hashes. Для шести ICVI совпадают структура, статусы, причины, формулы и направления; конечные числа имеют прежний допуск `rtol=1e−10, atol=1e−12`. Для пообъектного SW — `rtol=0, atol=1e−12`. Непрохождение — ошибка переноса/исполнения, а не новый научный результат и не основание принять удобную альтернативу.

## Показатели, которые будут прочитаны

1. **Устойчивость относительно собственного полного разбиения.** Для каждого месяц × K × метод: средний и минимальный ARI и macro-J по десяти draw. Соответствие выбирается максимизацией суммы Jaccard; исчезнувшая исходная группа явно сохраняется с нулевым J, не выкидывается. Для каждой полной группы — средний/минимальный J и число исчезновений.
2. **Геометрия на той же опоре.** Все шесть ICVI со статусами; средний SW и число отрицательных SW. Разности с сохранённым K10 вычисляются попарно по тем же ID и нормировке. Разница K учитывается при интерпретации: рост ARI или SW сам по себе не доказывает лучший экономический результат.
3. **Исходная декабрьская G7.** Ровно 182 ID из принятого декабрьского NCut10, сохранённые в `SUPPORTS.json`. Для полного декабря и каждого декабрьского draw: сколько этих ID присутствует, средний/отрицательные SW, распределение по новым группам. G7 не переопределяется по новым меткам. На июнь её номер не переносится.
4. **Цена укрупнения.** Для каждого нового декабрьского назначения — вся таблица исходные G0–G9 × новое K, доля G7, профили в исходных рублях и покрытый контекст. Внутри каждой новой группы отдельно показываются исходные участники G7 и остальные. Особое содержательное чтение заранее задано для контрастов G7 с G0/G3/G6/G8/G9; остальные происхождения также не скрываются. Медианы и квартили, размер опоры и охват контекста обязательны. Эти таблицы показывают смешение/сохранение различий без нового подогнанного порога «смысл сохранён».

Индекс доступности рынков, население и зарплата охваченных организаций описывают только доступный контекст 2024 года. Они не становятся новыми признаками обучения, независимыми причинными доказательствами или доходом жителей. Total остаётся модельной оценкой средних безналичных расходов жителей за месяц, а не оборотом территории.

## Как читать возможные исходы

| Исход | Допустимый вывод |
|---|---|
| Полная численная parity не пройдена | Остановить научную интерпретацию; разобраться с переносом, не объявлять новую версию улучшением |
| Устойчивость и геометрия лучше, измеренные контрасты достаточно различимы в показанных таблицах | Основание обсудить более крупный исследовательский вид; отдельное решение с ревью, без автоматической замены K10 |
| SW/устойчивость лучше, но разные профили существенно смешиваются | Компромисс детализации, а не однозначное улучшение |
| Методы, месяцы или показатели дают разные направления | Зафиксировать смешанный результат целиком; не строить подобранный сводный балл |
| Последовательного выигрыша нет | Сохранить K10 и отрицательный вывод challenger-теста |
| Любой успешный исход | Не снимает прежнюю административную чувствительность, отрицательный тест hard/soft аналогов или отсутствие причинности динамики |

Все десять draw остаются знаменателем. При недоступном разбиении/незавершённом задании полное среднее не выдаётся как завершённое; отдельно маркируются число доступных результатов и условная статистика. Численные проходные пороги качества задним числом не вводятся. Критерии пригодности исполнения отделены от научного суждения.

## Ограничение ресурсов и выход

Целевой общий предел — 90 минут, включая закрытие, на шести CPU; это бюджет, а не обещание длительности. Два новых калибровочных задания определяют допуск оставшейся очереди с запасом на проверку/архив. Общий операторский край — 9 октября 16:30 UTC. Автоповторов, дополнительных K, новых источников, изменений весов/графа или K10-fit нет. SSH и запуск выполняет только root.

`collect_results.py` читает только реальные sealed outputs: проверяет COMMIT/владельцев/метрики исходным валидатором, full parity, собственную устойчивость и парное сравнение с сохранённым K10. Выходы: `CELLS.json`, `STABILITY_SUMMARY.json`, `PAIRED_K10.json`, `G7_CONTENT.json`, `READBACK.json`. Сборщик не обучает модели, не переименовывает группы и не выносит автоматическое решение о победителе. Окончательная интерпретация требует отдельного независимого чтения.
