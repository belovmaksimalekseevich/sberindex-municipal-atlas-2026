# Сходство муниципалитетов

Интерактивный атлас потребительских расходов: 2 190 территорий, 24 месяца 2023–2024 годов и 50 521 опубликованное наблюдение. У 2 016 территорий есть все 24 месяца. Пропуск публикации остаётся пропуском.

В одном репозитории собраны интерактивный атлас, научный код, входные данные, сохранённые результаты и документы. Интерфейс и адаптивная композиция основаны на проекте Евгения Захарова; интеграция исследовательских данных и финальная сборка выполнены Максимом Беловым.

Команда **venik**: Белов Максим, Евгений Захаров, Егор Евлахов.

Атлас помогает проверить, чем похожи территории и что скрывает общая метка группы. Например, для Екатеринбурга близость общих расходов и близость социально-экономического контекста дают разный порядок аналогов. Сеть, подробные и укрупнённые профили и паспорта позволяют разобрать это различие по исходным показателям. Проверенные сценарии приведены в разделе 10 [отчёта](docs/report.pdf). Дополнительные таблицы, протоколы и поправки собраны в [указателе доказательств](docs/EVIDENCE_GUIDE.md).

## Проверка из чистого клона

Для сайта нужны Git и Node.js 22.12 или новее с npm. Для научных проверок и расчётов нужен Python 3.11. Все входные данные уже включены в репозиторий. Доступ к нашей ВМ, ключи и дополнительные архивы не нужны. Интернет требуется для клонирования и установки зависимостей.

```text
git clone https://github.com/belovmaksimalekseevich/sberindex-municipal-atlas-2026.git
cd sberindex-municipal-atlas-2026
node --version
npm --version
```

Дальше выполняйте команды из этого каталога, где лежат `package.json`, `research/` и `experiments/`. При скачивании ZIP вместо клонирования сначала распакуйте его и перейдите в этот же корневой каталог.

| Что проверить | Маршрут | Результат |
|---|---|---|
| Сохранённые научные результаты | Следующий раздел | Проверены 504 месячных и 28 контекстных разбиений |
| Сборку и работу сайта | [Запуск сайта](#запуск-сайта) | Готовый `dist/` и атлас в браузере |
| Повтор опубликованного месяца | [Декабрьский SSE6 по JSON](experiments/README.md) | Новый расчёт и сравнение групп и показателей с принятым результатом |
| Всю основную сетку заново | [Полный пересчёт](docs/FULL_REPLAY.md) | 504 + 28 новых разбиений и их проверка; нужен отдельный Linux-ресурс |

Для автоматической проверки достаточно сначала проверить сохранённые результаты, затем выполнить `npm ci` и `npm run check`. Эти команды завершаются сами. Сервер `preview` и вычисления запускаются отдельно, когда нужен соответствующий результат.

## Проверка сохранённых результатов

В Windows PowerShell:

```powershell
py -3.11 -B research/release.py verify
```

В Linux:

```bash
python3.11 -B research/release.py verify
```

Если Python 3.11 доступен в окружении под именем `python`, та же команда: `python -B research/release.py verify`. Для этого шага достаточно стандартной библиотеки: устанавливать NumPy или запускать обучение не требуется.

Признак успеха — код завершения 0 и JSON с `passed: true`, `new_fits: 0`, `national: 504`, `context: 28`. Это проверка сохранённых файлов. Она сверяет состав поставки, SHA-256, ID, размеры групп и статусы показателей; новый расчёт не выполняется. Для S_Dbw ожидаются 175 значений со статусом `ok` и 329 `undefined` — неопределённый индекс сохранён с причиной и не считается ошибкой проверки.

Не создавайте виртуальное окружение, результаты или `__pycache__` внутри `research/`: этот каталог проверяется по точному составу. Во всех Python-командах ниже указан `-B`, чтобы не создавать кеш байткода.

## Что сравнивается

| Представление | Роль |
|---|---|
| NCut10 | Подробная сетевая типология из десяти расходных профилей |
| SSE10 | Другой метод при таком же числе групп |
| SSE6 | Самостоятельный укрупнённый обзор из шести профилей |

В среднем SSE6 устойчивее в двух проверенных месяцах, июне и декабре 2024, на десяти фиксированных 80%-ных подвыборках. При этом теряется часть детализации; превосходство по всем метрикам не установлено. Шесть и десять групп не складываются и не образуют установленную иерархию.

Отдельный годовой контекст 2024 года охватывает 1 666 территорий и 69 регионов. Его KMeans6 не является месячным SSE6. Рёбра показывают близость наблюдаемых профилей расходов, а не торговые или денежные потоки. Модельные расходы не равны доходам жителей или обороту экономики.

## Запуск сайта

Установите зависимости и выполните конечную проверку проекта:

```text
npm ci
npm run check
```

`check` последовательно проверяет исходные данные, линтер, 25 сценариев обработки отказов, типы, сборку, данные готового сайта и оба PDF. При первой ошибке команда останавливается с ненулевым кодом. Признак успеха — код 0; последняя проверка выводит JSON с `passed: true`. В `dist/` должны появиться `index.html`, файлы приложения и `docs/report.pdf`, `docs/presentation.pdf`. Вывод npm содержит служебные строки перед JSON, поэтому целиком разбирать его как один JSON-документ не нужно.

Теперь отдельно запустите сервер готовой сборки:

```text
npm run preview -- --host 127.0.0.1 --port 4173 --strictPort
```

Откройте **http://127.0.0.1:4173/**. Сервер остаётся работать в этом терминале; это нормальное поведение. Для остановки нажмите `Ctrl+C`. Если порт занят, остановите прежний сервер или задайте `--port 4174` и откройте адрес с этим портом.

На странице должны открываться карта, группы и паспорт территории. Переключите месяц и представление, затем в разделе «Как получено» скачайте отчёт и презентацию. Сайт читает уже сохранённые данные; выбор месяца не запускает расчёт модели. Открывать `index.html` двойным щелчком вместо сервера не нужно.

Для разработки можно отдельно выполнить `npm run dev`; адрес напечатает Vite. Эту команду не ставят в середину списка конечных проверок: она также работает до `Ctrl+C`. Команды `typecheck`, `lint`, `test:runtime`, `build`, `verify:data`, `verify:dist` и `verify:documents -- --dist` доступны по отдельности. Алиасы `site:dev`, `site:build` и `site:preview` сохранены.

`verify:data` сверяет 35 файлов принятых данных и два справочных географических файла по SHA-256. `verify:dist` дополнительно проверяет 28 файлов данных готовой сборки. Эти команды читают сохранённые файлы и не обучают модели.

`verify:documents -- --dist` проверяет наличие отчёта и презентации в PDF и их побайтное совпадение с файлами готового сайта. Исходники этих двух документов в публичную поставку не входят.

Предупреждение Vite о размере JS-файла возможно: в приложение включены научные данные. Само предупреждение не означает сбой сборки; итог определяется кодом завершения и последующими проверками. Если команда завершилась с ошибкой, сохраните её вывод и сначала устраните причину, затем продолжайте маршрут.

## Новый расчёт

[Инструкция расчёта](experiments/README.md) содержит отдельные команды для Windows и Linux: создание окружения, установку точных версий библиотек, проверку JSON и повтор SSE6 за декабрь 2024 года. Используются восемь исходных начальных состояний. После расчёта отдельная команда сравнивает все 2 103 ID, состав и размеры групп, шесть показателей и индивидуальные значения силуэта с опубликованным результатом. Успех отмечается как `SSE6_DECEMBER_READBACK_PASS`; это проверка одного месяца, а не всей сетки.

Там же описан самостоятельный эксперимент с изменяемыми параметрами JSON. Он сохраняется отдельно и не подменяет данные сайта. При другой конфигурации результат может отличаться от принятой модели.

[Инструкция полного пересчёта](docs/FULL_REPLAY.md) описывает требования к Linux, предварительную проверку машины, запуск всей основной сетки и чтение результата. Это отдельная длительная операция, которая не входит в `npm run check` и быструю проверку научных файлов. Проверка сохранённой поставки не выдаётся за повтор этого расчёта.

## Публикация

Workflow GitHub Pages запускает установку зависимостей, линтер, проверки обработки отказов, проверку типов и сборку. При push в `main` или ручном запуске публикуется содержимое `dist/`. В Settings → Pages должен быть выбран источник GitHub Actions. Локальная сборка сама по себе не обновляет сайт; история исходного интерфейса сохраняется.

В [GitHub Actions](https://github.com/belovmaksimalekseevich/sberindex-municipal-atlas-2026/actions) можно посмотреть проверку конкретного коммита. `Pages` выполняет `npm ci` и тот же `npm run check`. `Model configuration` устанавливает Python-зависимости, проверяет код и сохранённые результаты, затем заново рассчитывает декабрьский SSE6 с восемью исходными начальными состояниями и сверяет его с опубликованными группами и показателями. Файлы расчёта сохраняются как артефакт. Успех этого повтора подтверждает рабочий путь для одного месяца; он не означает пересчёт всей сетки или обновление модели на сайте.
