# Сходство муниципалитетов

Интерактивный атлас потребительских расходов: 2 190 территорий, 77 регионов, 24 месяца 2023–2024 годов и 50 521 наблюдение.

Атлас помогает сравнивать муниципалитеты по уровню и структуре расходов, находить похожие территории и изучать изменения во времени. Карта, сеть сходства и паспорта территорий связывают общую картину с конкретными показателями. Например, для Екатеринбурга можно сопоставить ближайшие аналоги по расходам и по социально-экономическому контексту и увидеть, в каких показателях они различаются. Примеры работы с атласом приведены в разделе 10 [отчёта](docs/report.pdf).

Команда **venik**: Максим Белов, Евгений Захаров, Егор Евлахов. Интерфейс подготовил Евгений Захаров, интеграцию исследовательских данных и итоговую сборку выполнил Максим Белов.

## Группы и сравнения

| Представление | Для чего использовать |
|---|---|
| NCut10 | Подробный разбор десяти расходных профилей и сети сходства |
| SSE10 | Сравнение методов при одинаковом числе групп |
| SSE6 | Обзор шести укрупнённых профилей |

Устойчивость SSE6 проверена на десяти подвыборках из 80% территорий для каждого из двух месяцев. Средний ARI составил **0,947 в июне и 0,925 в декабре 2024 года**. Этот показатель отражает сходство разбиений при изменении состава данных; значение 1 означает полное совпадение. Подробные результаты доступны в [таблице устойчивости](src/landing/i26/stability_SSE6.json).

Годовой социально-экономический контекст дополняет расходные профили данными о 1 666 территориях из 69 регионов: численностью населения, доступностью рынков, зарплатами и занятостью в организациях.

## Проверка из чистого клона

Для сайта нужны Git и Node.js 22.12 или новее с npm. Для научных проверок и расчётов нужен Python 3.11. Все входные данные включены в репозиторий. Интернет требуется для клонирования и установки зависимостей.

```text
git clone https://github.com/belovmaksimalekseevich/sberindex-municipal-atlas-2026.git
cd sberindex-municipal-atlas-2026
node --version
npm --version
```

Дальше выполняйте команды из этого каталога, где лежат `package.json`, `research/` и `experiments/`. При скачивании ZIP вместо клонирования сначала распакуйте его и перейдите в этот же корневой каталог.

| Что проверить | Маршрут | Результат |
|---|---|---|
| Сохранённые научные результаты | Следующий раздел | Проверены 504 месячных и 28 контекстных разбиений |
| Сборку и работу сайта | [Запуск сайта](#запуск-сайта) | Готовый `dist/` и атлас в браузере |
| Повтор опубликованного месяца | [Декабрьский SSE6 по JSON](experiments/README.md) | Новый расчёт и сравнение групп и показателей с принятым результатом |
| Всю основную сетку заново | [Полный пересчёт](docs/FULL_REPLAY.md) | 504 + 28 новых разбиений и их проверка; нужен отдельный Linux-ресурс |

Для автоматической проверки сначала выполните проверку сохранённых результатов, затем `npm ci` и `npm run check`. Эти команды завершаются сами. Сервер `preview` и вычисления запускаются отдельно.

## Проверка сохранённых результатов

В Windows PowerShell:

```powershell
py -3.11 -B research/release.py verify
```

В Linux:

```bash
python3.11 -B research/release.py verify
```

Если Python 3.11 доступен в окружении под именем `python`, та же команда: `python -B research/release.py verify`. Для этого шага достаточно стандартной библиотеки Python.

Признак успеха — код завершения 0 и JSON с `passed: true`, `new_fits: 0`, `national: 504`, `context: 28`. Команда проверяет сохранённые файлы: их состав, контрольные суммы, ID, размеры групп и статусы показателей. Для S_Dbw ожидаются 175 значений со статусом `ok` и 329 `undefined`; причина неопределённого значения указана в результате.

Создавайте виртуальное окружение и результаты вне `research/`: состав этого каталога проверяется автоматически. Параметр `-B` в Python-командах отключает создание кеша байткода.

## Запуск сайта

Установите зависимости и выполните конечную проверку проекта:

```text
npm ci
npm run check
```

`check` последовательно проверяет исходные данные, линтер, 25 сценариев обработки отказов, типы, сборку, данные готового сайта и оба PDF. При первой ошибке команда останавливается с ненулевым кодом. Признак успеха — код 0; последняя проверка выводит JSON с `passed: true`. В `dist/` должны появиться `index.html`, файлы приложения и `docs/report.pdf`, `docs/presentation.pdf`. Вывод npm содержит служебные строки перед JSON, поэтому целиком разбирать его как один JSON-документ не нужно.

Теперь отдельно запустите сервер готовой сборки:

```text
npm run preview -- --host 127.0.0.1 --port 4173 --strictPort
```

Откройте **http://127.0.0.1:4173/**. Сервер остаётся работать в этом терминале; это нормальное поведение. Для остановки нажмите `Ctrl+C`. Если порт занят, остановите прежний сервер или задайте `--port 4174` и откройте адрес с этим портом.

На странице откройте карту, группы и паспорт территории. Переключите месяц и представление, затем в разделе «Как получено» скачайте отчёт и презентацию. Сайт показывает сохранённые результаты для выбранного месяца. Для работы с данными используйте сервер, а не открытие `index.html` двойным щелчком.

Для разработки выполните `npm run dev`; адрес напечатает Vite. Сервер работает до `Ctrl+C`. Команды `typecheck`, `lint`, `test:runtime`, `build`, `verify:data`, `verify:dist` и `verify:documents -- --dist` доступны по отдельности. Также доступны `site:dev`, `site:build` и `site:preview`.

`verify:data` сверяет контрольные суммы 35 файлов данных и двух географических справочников. `verify:dist` дополнительно проверяет 28 файлов данных готовой сборки.

`verify:documents -- --dist` проверяет наличие отчёта и презентации в PDF и их совпадение с файлами готового сайта.

Предупреждение Vite о размере JS-файла возможно: в приложение включены научные данные. Само предупреждение не означает сбой сборки; итог определяется кодом завершения и последующими проверками. Если команда завершилась с ошибкой, сохраните её вывод и сначала устраните причину, затем продолжайте маршрут.

## Новый расчёт

[Инструкция расчёта](experiments/README.md) содержит команды для Windows и Linux: создание окружения, установку библиотек, проверку JSON и повтор SSE6 за декабрь 2024 года. Используются восемь исходных начальных состояний. После расчёта отдельная команда сравнивает все 2 103 ID, состав и размеры групп, шесть показателей и индивидуальные значения силуэта с опубликованным результатом. Признак успеха — `SSE6_DECEMBER_READBACK_PASS`. Такой повтор успешно выполнен на Windows и Linux; файлы расчёта доступны в [GitHub Actions](https://github.com/belovmaksimalekseevich/sberindex-municipal-atlas-2026/actions/workflows/experiments.yml).

Там же описаны эксперименты с собственными параметрами JSON. Для каждого запуска создаётся отдельный каталог результатов.

[Полный пересчёт](docs/FULL_REPLAY.md) охватывает основную сетку из 504 месячных и 28 контекстных разбиений. В инструкции указаны требования к Linux, проверка машины перед запуском и команды проверки результата. Этот длительный расчёт запускается отдельно от `npm run check`.

## Ограничения и интерпретация

- Группы описывают наблюдаемые расходы. Их нельзя напрямую трактовать как типы всей экономики, уровень доходов или торговые потоки. Сеть отражает сходство расходных профилей.
- Проверка устойчивости SSE6 относится к июню и декабрю 2024 года. Шесть групп дают более общий обзор, десять — более подробный; это самостоятельные разбиения, а не установленная иерархия. Годовой KMeans6 также рассчитывается отдельно.
- Территории относятся к разным административным типам. Полный ряд из 24 месяцев есть у 2 016 территорий; пропуски публикации сохраняются как пропуски. Смена группы описывает изменение профиля расходов и не означает миграцию жителей или установленную причину экономических изменений.
- Экранная сеть сокращена для читаемости, а её расположение условно. Для SSE она иллюстрирует сходство данных; этот метод обучается без входного графа.
- Подбор аналогов служит исследованию и сравнению территорий. Проведённый тест не подтвердил пользу обязательного отбора аналогов внутри кластера. Эффект использования атласа в управленческих решениях требует отдельной проверки на практике.
