# Настройка и запуск эксперимента

Здесь можно изменить гиперпараметры модели в JSON и заново рассчитать один месяц на опубликованных входных данных. Поддерживаются SSE, NCut и Ward. Доступны число групп K, месяц, начальные состояния генератора случайных чисел, параметры графа NCut и предел итераций оптимизатора.

Принятые 532 разбиения хранятся в `research/`. Эксперимент создаёт отдельный результат и не меняет данные атласа. Для точного повторения всей принятой сетки служит [полный пересчёт](../docs/FULL_REPLAY.md).

## Повторить опубликованный SSE6 за декабрь 2024

Нужен Python 3.11. Все команды выполняются **из корня скачанного репозитория** — папки с `README.md`, `experiments/` и `research/`. Входные данные уже опубликованы в репозитории; доступ к прежней виртуальной машине не нужен. Установка зависимостей требует доступа к PyPI.

Для этого маршрута служит `replay-sse6-december.json`: весь декабрьский набор из 2103 территорий, SSE, 6 групп, исходные восемь seeds, предел 300 итераций и один поток. Настройки взяты из принятой модели. После нового расчёта отдельная команда сравнит результат с опубликованным SSE6. Это проверка одного месяца; полный пересчёт всех 532 разбиений описан [отдельно](../docs/FULL_REPLAY.md).

Окружение и результат создаются рядом с репозиторием, вне его папки. Если эти пути уже существуют, выберите другие имена и используйте их во всех следующих командах. Активировать окружение не требуется: в каждой команде ниже указан его Python.

### Windows PowerShell

```powershell
py -3.11 -m venv ..\sberindex-venv
& "..\sberindex-venv\Scripts\python.exe" -m pip install -r research/code/requirements-compute.txt
& "..\sberindex-venv\Scripts\python.exe" -B experiments/run.py plan --config experiments/configs/replay-sse6-december.json
& "..\sberindex-venv\Scripts\python.exe" -B experiments/run.py run --config experiments/configs/replay-sse6-december.json --out ../sberindex-sse6-december
& "..\sberindex-venv\Scripts\python.exe" -B -S scripts/check-sse6-replay.py --out ../sberindex-sse6-december --receipt ../sberindex-sse6-december.check.json
```

Если `py -3.11` не найден, установите Python 3.11 с Python Launcher либо замените только первую команду вызовом полного пути к установленному `python.exe` версии 3.11. Остальные команды используют уже созданное окружение.

### Linux и macOS

```bash
python3.11 -m venv ../sberindex-venv
"../sberindex-venv/bin/python" -m pip install -r research/code/requirements-compute.txt
"../sberindex-venv/bin/python" -B experiments/run.py plan --config experiments/configs/replay-sse6-december.json
"../sberindex-venv/bin/python" -B experiments/run.py run --config experiments/configs/replay-sse6-december.json --out ../sberindex-sse6-december
"../sberindex-venv/bin/python" -B -S scripts/check-sse6-replay.py --out ../sberindex-sse6-december --receipt ../sberindex-sse6-december.check.json
```

Для создания окружения у Python 3.11 должен быть доступен модуль `venv`.

### Что проверяет каждая команда

`plan` проверяет JSON и контрольные суммы научного комплекта. Он выводит месяц, число наблюдений `N`, параметры, ожидаемое число попыток и требуемые версии библиотек. Для этой команды достаточно стандартной библиотеки; она не обучает модель и не проверяет работоспособность установленных численных библиотек.

`run` загружает опубликованные наблюдения и **заново запускает кластеризацию** с выбранными параметрами. Команда проверяет версии библиотек, сохраняет результат в отдельную папку и не меняет сайт, отчёт или принятые разбиения. Время зависит от месяца, метода и числа начальных состояний.

`check-sse6-replay.py` ничего не обучает. Статус `SSE6_DECEMBER_READBACK_PASS` означает, что сверены конфигурация и восемь попыток, происхождение файлов, все 2103 ID, состав шести групп и их размеры, шесть индексов качества и все индивидуальные SW. Номера групп могут быть взаимно однозначно переименованы; принадлежность территорий должна совпасть точно. Числа сравниваются по ранее принятому правилу: `abs(a-b) <= 2e-11 + 2e-10 * max(abs(a), abs(b))`.

Это сверка результата одной опубликованной модели, а не побайтное сравнение JSON, всех промежуточных матриц или полный национальный прогон. Хеши графов могут различаться между платформами. Команда проверки читает уже созданные файлы; сама по себе она не доказывает, какой процесс их создал. Значения квартилей расходных профилей она отдельно не сравнивает.

При проверке этой инструкции новый расчёт с восемью начальными состояниями на Windows/Python 3.11 завершился успешно: все 2103 метки и размеры групп, шесть метрик и все индивидуальные SW совпали с опубликованным результатом. Это не подтверждение полного прогона на Linux или других месяцах.

## Свои параметры и повторный запуск

Для собственных экспериментов в `experiments/configs/` находятся `sse.json` с одним seed, `ncut.json`, `ncut-radius.json` и `ward.json`. Результаты таких опытов могут отличаться от принятых меток. Скопируйте нужный JSON за пределы репозитория и измените поля. Комментарии, `NaN`, бесконечность, повторяющиеся и неизвестные поля не допускаются.

Например, в PowerShell:

```powershell
Copy-Item experiments/configs/sse.json ../my-sse.json
# Отредактируйте ../my-sse.json, затем проверьте и запустите его:
& "..\sberindex-venv\Scripts\python.exe" -B experiments/run.py plan --config ../my-sse.json
& "..\sberindex-venv\Scripts\python.exe" -B experiments/run.py run --config ../my-sse.json --out ../sberindex-sse-experiment-02
```

В Linux и macOS:

```bash
cp experiments/configs/sse.json ../my-sse.json
# Отредактируйте ../my-sse.json, затем проверьте и запустите его:
"../sberindex-venv/bin/python" -B experiments/run.py plan --config ../my-sse.json
"../sberindex-venv/bin/python" -B experiments/run.py run --config ../my-sse.json --out ../sberindex-sse-experiment-02
```

Каждый вызов `run` требует **нового выходного каталога**. Готовая или частично заполненная папка не перезаписывается; автоматического продолжения нет. После прерывания сначала проверьте файлы `COMMIT.json` и `FAILED.json`, если они появились, и сообщение команды. Если повтор нужен, сохраните прежнюю папку и укажите новый путь после `--out`. Не запускайте одновременно два процесса с одним выходным путём. Для новой квитанции проверки также выбирайте свободное имя после `--receipt`: существующий файл не перезаписывается. Ошибка сверки сама по себе не запускает расчёт повторно.

## Параметры JSON

| Поле | Допустимые значения и смысл |
|---|---|
| `schema` | `municipal-experiment-v1` |
| `month` | Месяц от `2023-01` до `2024-12`; используется весь опубликованный месячный набор наблюдений |
| `method` | `SSE`, `NCut` или `Ward` |
| `K` | Целое число групп от 2 до 20 |
| `seeds` | Для SSE/NCut от 1 до 8 различных целых чисел от 0 до 4294967295; для Ward пустой список `[]` |
| `graph` | Для NCut объект с параметрами ниже; для SSE/Ward `null`, поскольку эти методы не обучаются на графе |
| `optimizer` | Для SSE/NCut объект `{"max_iterations": 300}`, допустимо от 1 до 1000; для Ward `null` |
| `threads` | От 1 до 8 потоков численных библиотек; это ресурсная настройка, а не гиперпараметр модели |

Для графа NCut доступны два правила:

```json
{"kind": "union", "k": 15, "sigma": 1.0, "radius": null}
```

```json
{"kind": "radius", "k": null, "sigma": 1.0, "radius": 1.5}
```

`union` объединяет связи k ближайших соседей с сохранением точных ничьих по расстоянию. `k` допускает значения от 1 до 128 и должен быть меньше числа наблюдений. `radius` соединяет пары в заданном радиусе. Для обоих правил веса определяет гауссово ядро с масштабом `sigma`. Значения `sigma` и ненулевого `radius` должны находиться от 0,05 до 10. Неиспользуемое поле задаётся как `null`.

Новые настройки могут дать граф с изолированными узлами или разбиение, для которого не определены отдельные индексы. Такие случаи должны читаться по статусам результата; они не означают нулевое значение метрики или улучшение модели. Если выбранные начальные состояния не дали сошедшегося решения в пределах `max_iterations`, готовое разбиение не объявляется полученным.

Оптимизатор использует точные правила исходного Lloyd. Параметра `tol` в этом ядре нет: добавлять его в JSON нельзя. Меняется реальный предел `max_iterations`, передаваемый вычислительной функции.

## Смысл результата

Расходные признаки, обработка наблюдений и масштабирование берутся из принятого научного комплекта. Признаки описывают уровень и структуру расходов, а не доходы жителей или денежные потоки между территориями.

Пользовательский граф определяет обучение NCut. Общий граф оценки качества остаётся прежним: радиус 1,5 и `sigma=1`. Такое разделение позволяет оценивать новые разбиения в общей геометрии. Изменение `graph` не меняет граф оценки. Значения собственной целевой функции NCut для разных графов напрямую не сопоставимы.

В папке результата сохраняются:

| Файл | Содержимое |
|---|---|
| `PLAN.json`, `config.json` | Проверенный план, число наблюдений и фактически использованные настройки |
| `labels.json` | Полный список ID выбранного месяца и присвоенные метки, если разбиение получено |
| `result.json` | Разбиение, размеры и профили групп, индексы качества и их статусы |
| `attempts.json` | Попытки оптимизации и исход каждого seed-запуска; для Ward список пуст |
| `provenance.json` | Версии Python и библиотек, параметры, время, происхождение входов и кода, контрольные суммы |
| `COMMIT.json` | Итоговый статус и контрольные суммы файлов результата |

`COMMIT.json` со статусом `completed` и код завершения 0 означают, что получено разбиение. Статус `unavailable` и код 3 означают, что заданные условия не дали готового разбиения; это не успешная модель с нулевыми метриками. При ошибке после начала расчёта может сохраниться `FAILED.json` с причиной. Ошибки JSON, входов или выходного пути могут завершить команду до создания папки.

Статусы неопределённых метрик сохраняются даже при полученном разбиении. Результат отмечается как экспериментальный, `model_promoted=false`; автоматической замены групп на сайте нет.

Совпадение метода и K с вариантом на сайте не означает, что новый опыт обязан повторить его метки: настройки начальных состояний и выбор представителя могут отличаться. Для точного повторения принятой сетки следуйте [инструкции полного пересчёта](../docs/FULL_REPLAY.md).

Один удачный запуск не устанавливает лучший метод, устойчивость на всех месяцах или практическую пользу группировки. Сравнивайте результаты на одинаковой опоре, проверяйте устойчивость и содержательный смысл. Числа на сайте и в отчёте относятся к ранее принятой модели.

## Проверка кода и сохранённых результатов

После установки зависимостей, из корня репозитория.

Windows PowerShell:

```powershell
& "..\sberindex-venv\Scripts\python.exe" -B -m unittest discover -s experiments -p "test_*.py"
& "..\sberindex-venv\Scripts\python.exe" -B research/release.py verify
```

Linux и macOS:

```bash
"../sberindex-venv/bin/python" -B -m unittest discover -s experiments -p "test_*.py"
"../sberindex-venv/bin/python" -B research/release.py verify
```

Первая команда проверяет режим конфигурации, в том числе недопустимые параметры и защиту выходных путей. Вторая проверяет неизменность принятого научного комплекта и 532 сохранённых разбиений без повторения полного обучения. Тестовые примеры не являются новыми научными результатами.
